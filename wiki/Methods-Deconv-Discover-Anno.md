# Methods Text for `sniffcell deconv`, `sniffcell discover`, and `sniffcell anno`

## SniffCell deconv

SniffCell deconvolution estimates cell-type composition from long-read methylation data using an input BAM, a reference FASTA, and an annotation-ready ctDMR table generated by `sniffcell find`. For each ctDMR, CpG positions are recovered from the reference genome and a per-read methylation matrix is assembled from BAM base-modification tags. SniffCell combines 5mC and 5hmC probabilities into a single methylated state and removes reads or regions that do not contain informative CpG measurements. Because atlas ctDMRs are stored in a G-anchored coordinate system, the queried interval is shifted by 1 bp at the left edge during methylation extraction to ensure consistent recovery of the leading CpG.

Within each ctDMR, SniffCell classifies each read as supporting the ctDMR target group or its complement. In the default `closest_reference_mean` mode, the mean methylation value of each read across CpGs in the ctDMR is compared with the atlas-derived `mean_best_value` and `mean_rest_value`, and the read is assigned to the closer reference state. As an alternative, `kmeans` mode performs two-cluster unsupervised partitioning of read methylation profiles and then orients the clusters using ctDMR directionality and the reference methylation means. Each ctDMR contributes a binary code in a shared cell-type schema, where bits set to 1 denote the leaf cell types represented by the target group and bits set to 0 denote the complementary set.

SniffCell then aggregates evidence across ctDMRs at the read level. For each read, binary codes observed across all covered ctDMRs are combined by bitwise intersection, which preserves compatible hierarchical assignments rather than forcing a single flat label prematurely. When the intersection collapses to an empty solution, SniffCell falls back to plurality voting and accepts the plurality code only if its support exceeds a user-defined minimum agreement threshold; otherwise the read is labeled as mixed. The workflow reports row-level ctDMR classifications, a per-read consensus table containing primary and linked cell-type labels, and sample-level summaries in both all-evidence and per-read modes. Optionally, reads can be split into user-defined groups and written back out as per-group TSV and BAM files for downstream analyses.

## SniffCell anno

SniffCell annotation assigns cell-type methylation evidence to candidate variants by combining long-read methylation measurements with a ctDMR reference. The command accepts either a structural-variant VCF or a harmonized variant table generated by `sniffcell discover`. Before per-read classification, the ctDMR table is restricted to loci that fall within a user-defined window around the candidate variants. ctDMRs that overlap the variant core are excluded, and this exclusion zone can be expanded in proportion to the absolute variant size to suppress signals immediately adjacent to breakpoints.

For each retained ctDMR, SniffCell extracts the local methylation matrix from the BAM and classifies reads using the same per-ctDMR procedure described for deconvolution. Each read-ctDMR observation is represented as a hierarchical binary code together with the associated cell-type schema. Variant-level evidence is then assembled in two steps. First, ctDMR intervals are linked to variants by genomic proximity. Second, only reads that are both assigned to a linked ctDMR and listed among the variant-supporting reads are retained as methylation evidence for that variant. When multiple ctDMRs support the same read, SniffCell computes a per-read consensus code by bitwise intersection; reads with unresolved conflicts are marked as mixed and excluded from downstream voting.

Variant-level assignment is based on one consensus vote per supporting read. For each variant, SniffCell reports the number of supporting reads, the number overlapping informative ctDMRs, the number of mixed reads removed from voting, the majority binary code, and the agreement fraction among retained votes. The binary codes are decoded back into human-readable linked cell-type labels using the hierarchy embedded in the ctDMR schema, and SniffCell summarizes per-cell-type counts and fractions for each variant. A final `assigned_code` is emitted only when the variant satisfies user-defined overlap and agreement thresholds and no hard conflict remains among the retained read-level constraints. Variants that fail these criteria are preserved in the output table as unassigned, allowing downstream review without discarding the underlying methylation evidence.

## SniffCell discover

SniffCell discovery is a two-group post-processing workflow that operates on split BAMs produced from `sniffcell deconv`. The command reads the group-split manifest, resolves the selected deconvolution groups, and runs a staged comparison of their structural-variant, tandem-repeat, and methylation profiles. In the structural-variant branch, Sniffles is run independently on each split BAM in mosaic mode with read-name reporting enabled. PASS-filtered callsets are optionally further restricted with a mosaic-expression filter, then converted to sample-agnostic site sets and merged across groups. The merged site list is collapsed with Truvari to define a nonredundant set of candidate loci, which are then re-genotyped jointly against both BAMs using Kanpig. Final structural-variant calls are classified as group A-specific, group B-specific, or shared using allele-depth logic with configurable minimum depth and alternate-read thresholds, and supporting read names are retained for each group.

In parallel, SniffCell can process tandem-repeat variation between the same two split groups. Medaka tandem is run separately on each group-specific BAM, per-group TDB databases are created, and the group databases are merged for comparative post-processing. The tandem-repeat post-processing step combines merged TDB summaries with Medaka trimmed-read sequences to identify haplotype-resolved repeat-length differences between the two groups and to label the changed and baseline groups at each locus. Optional branches can additionally produce CpG pileup summaries with Modkit and small-variant callsets with Clair3 and ClairS.

At the end of the workflow, SniffCell harmonizes the structural-variant and tandem-repeat outputs into a single tab-delimited variant table. This harmonized table records genomic coordinates, variant class, subtype, group-specific alternate-read counts, and group-specific supporting read names, and is designed to serve directly as input to downstream `sniffcell anno` runs. The workflow can be executed locally or rendered as SLURM submission scripts, but the analytical logic and output schema are identical across execution modes.
